۱. خلاصه مدیریتی

این پروژه یک سامانه وب تمام‌پشته برای مدیریت چرخه کامل انرژی در یک ریزشبکه دانشگاهی است. سامانه داده‌های مصرف تجهیزات را دریافت می‌کند، ظرفیت پنل خورشیدی و باتری را در محاسبات وارد می‌سازد، شاخص‌های تحلیلی را نمایش می‌دهد و امکان معامله انرژی مازاد میان کاربران را فراهم می‌کند.

رابط فارسی و راست‌به‌چپ، نقش‌های کاربر و مدیر، ثبت‌نام امن با رمز یک‌بارمصرف، نمودارهای زمانی و پنل عملیاتی، پروژه را به نمونه‌ای قابل توسعه برای مدیریت انرژی هوشمند تبدیل می‌کنند.

۲. مسئله، اهداف و کاربران

مسئله

تولید خورشیدی و مصرف ساختمان معمولاً در ابزارهای جداگانه ثبت می‌شوند؛ بنابراین تصمیم‌گیری درباره ظرفیت ذخیره، ساعات اوج و فروش انرژی مازاد دشوار است. سامانه این داده‌ها را به جریان کاری واحد تبدیل می‌کند.

اهداف

  • شفاف‌سازی تولید و مصرف
  • کاهش مصرف ساعات اوج
  • بهینه‌سازی پنل و باتری
  • بازار کنترل‌شده انرژی
  • گزارش مدیریتی قابل اتکا

کاربران

  • ساکنان و بهره‌برداران واحدها
  • مدیران بلوک یا ساختمان
  • مدیر کل سامانه
  • ارزیابان و پژوهشگران

۵. شرح ماژول‌ها

احراز هویت و پروفایل

ثبت‌نام با OTP، ورود مبتنی بر توکن، تازه‌سازی نشست، بازیابی و تغییر رمز، مشخصات واحد و تصویر پروفایل.

داشبورد

شاخص‌های تولید، ذخیره، مصرف و مبادله را در کنار نمودارهای ۲۴ ساعته، ماهانه و فصلی ارائه می‌کند.

پنل خورشیدی و باتری

پنل ظرفیت تولید و باتری انرژی ذخیره و فروخته‌شده و وضعیت معامله را مدل می‌کنند.

تجهیزات، بلوک و آپارتمان

تجهیزات AC/DC و مشخصات ساختمانی، ورودی محاسبات واقعی مصرف هستند.

سوابق توان و قیمت‌گذاری

هر رکورد شامل تجهیز، شروع، پایان و مصرف است؛ تعرفه می‌تواند براساس فصل و بازه اوج اعمال شود.

فروشگاه، سفارش و پرداخت

پیشنهادها نمایش داده می‌شوند، مقدار خرید در محدوده موجودی اعتبارسنجی و سفارش خرید/فروش ثبت می‌شود.

مدیریت

مدیر سامانه کاربران و تجهیزات منتسب را با کنترل دسترسی نقش‌محور مدیریت می‌کند.

۶. سناریوها و جریان داده

  1. ورود: API توکن دسترسی و تازه‌سازی همراه نقش‌ها برمی‌گرداند و middleware مسیر را کنترل می‌کند.
  2. ثبت مصرف: تجهیز و بازه زمانی اعتبارسنجی و ذخیره می‌شوند؛ داشبورد داده تجمیع‌شده را دریافت می‌کند.
  3. خرید انرژی: باتری‌های در دسترس دریافت، مقدار معتبر تعیین و سفارش با فروشنده، باتری، مقدار و نرخ ثبت می‌شود.
  4. مدیریت: مدیر پس از بررسی scope به کاربران و منابع دسترسی می‌یابد.

اصل طراحی: رابط کاربری موفقیت جعلی نمایش نمی‌دهد؛ نتیجه تنها پس از پاسخ موفق API اعلام می‌شود.

۷. API و امنیت

/users/power-records/solar-panels/battery/device/blocks/products/users/orders

  • اعتبارسنجی با Pydantic و VeeValidate/Zod.
  • Authorization Bearer و تازه‌سازی نشست هنگام reload.
  • guard احراز هویت و نقش admin برای پنل.
  • عدم درج کلیدهای JWT، SMTP، پرداخت و Storage در گزارش.
  • HTTPS، cookie امن، CORS محدود و تعویض secrets در تولید ضروری است.

۹. راه‌اندازی

پیش‌نیاز: Docker و Docker Compose. فایل‌های محیطی را از نمونه‌ها بسازید و مقادیر امن وارد کنید.

cp .env.example .env
cp university-project/front/.app/.env.example university-project/front/.app/.env
docker compose up --build
  • وب: http://localhost
  • API: http://localhost:8002
  • Swagger: http://localhost:8002/docs
  • Mongo Express: http://localhost:8082

اجرای مستقل فرانت‌اند: pnpm install سپس pnpm dev از پوشه front.

۱۱. ارزش علمی

پروژه مهندسی نرم‌افزار تمام‌پشته، مدل‌سازی دامنه انرژی، تجمیع سری زمانی، امنیت نقش‌محور، تجربه کاربری فارسی و استقرار کانتینری را در نمونه‌ای عملی تلفیق می‌کند و مبنایی برای آزمایش پیش‌بینی بار و بهینه‌سازی ذخیره است.
